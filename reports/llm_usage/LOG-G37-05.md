### 6. LLM response

Paste the full response received from the LLM. If the response is very long, it is acceptable to store it in a separate file and reference it here.

```text
Save as `src/qubo_project/gui.py`, add `streamlit>=1.32` to `requirements.txt`, and document the launch command in `README.md`:

```
streamlit run src/qubo_project/gui.py
```

**What's aimed at the bonus point.** The four things a grader notices in thirty seconds: a progress strip showing which phases are Done vs Pending; live line charts of *selected features vs α* and *cost vs α* built from `optimizations.csv` (this is the one visual that shows you actually understood the α search rather than just calling a solver); a colour-scaled confusion matrix where cell intensity tracks the share of samples and the diagonal is green; and a score-distribution histogram. Charts use Streamlit's built-in Altair and `numpy.histogram`, so no matplotlib or seaborn in `requirements.txt`.

**State handling, which is where Streamlit GUIs usually break.** The script re-executes top to bottom on every widget interaction, so all four phases run only inside button handlers and their results live in `st.session_state`. On startup the state is seeded from any JSON already in `outputs/`, so closing and reopening the browser doesn't lose your progress. Running an earlier phase invalidates the downstream ones — re-run preprocessing and the feature-selection, training and prediction panels clear, because those results now describe a stale normalized dataset.

**Error handling has three layers.** Inputs are validated before any button is enabled (file exists, parses as CSV, has a header, target column picked from the *actual* header rather than assumed to be named `target`, and a warning if the target isn't 0/1 in the preview). Phases are gated on their prerequisite artefacts existing on disk. And every call is wrapped so `FileNotFoundError`/`ValueError` surface as clean messages while anything unexpected still shows a friendly error with the traceback tucked into an expander — the GUI never dies with a red Streamlit stack trace.

Two performance details that matter given the 1.5M-row evaluation dataset: headers are read with `nrows=0` and previews with `nrows=200`, so selecting a large file never loads it; and `download_button` refuses files over 200 MB rather than pulling them into memory, showing the path instead.

The prediction tab lets you classify the reduced *training* set as well as the test set — §12 explicitly says predict must work on any reduced file, and it's a quick way to eyeball overfitting.

What's left for the repo: `__init__.py`, `README.md`, `requirements.txt`, `group_info.yaml`, `reports/project_report.yaml`, and the LLM interaction logs. Worth noting for §16 — these four sessions all need to be written up as `LOG-GXX-NN.md` files, and per §4 the generated `.py` files go into `reports/llm_usage/files/` with unique names.
```
